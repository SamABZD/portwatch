# Decisions

| ID | Stage | Decision | Reason / revisit point |
| --- | --- | --- | --- |
| D-001 | 00 | Use a src-layout Python package and `python -m portwatch` Typer CLI. | Keeps pipeline entry points testable and separate from future presentation code. |
| D-002 | 00 | Use Python 3.11 locally, with project support through 3.14. | Python 3.12 is not installed on this machine; 3.11 is installed and mature for the selected dependencies. Recheck when a 3.12 interpreter is available. |
| D-003 | 00 | Use `postgis/postgis:16-3.5` in Compose with a localhost port and named volume. | Maintainer documentation lists PostgreSQL 16 with PostGIS 3.5 and the `/var/lib/postgresql/data` mount path. Image existence was verified from documentation, but this machine cannot run it until Docker is installed. [Maintainer reference](https://github.com/postgis/docker-postgis). |
| D-004 | 00, revised 01 | Use `[-118.34, 33.66, -118.225, 33.80]` as a heuristic Los Angeles collection box; keep `geofence_path` null. | Reviewed against the Port of Los Angeles terminal map and harbor reference points. This box is not an official boundary or analytical polygon; build and version that polygon later. See [SOURCE_AUDIT.md](SOURCE_AUDIT.md). |
| D-005 | 00, reviewed 01 | Retain provisional waiting thresholds of 1 knot, 30 minutes, and a 15-minute maximum observation gap. | Explicit analytical assumptions, not port facts. Validate against actual Los Angeles tracks before reporting waiting metrics. |
| D-006 | 00 | Treat live AIS credentials as optional. | Historical replay is the dependable $0 demo path. |
| D-007 | 00 | Store raw provider files under `data/raw/`, derived data under `data/derived/`, and rejected payloads under `data/quarantine/`. | Maintains source provenance and prevents synthetic or transformed records from replacing source evidence. |
| D-008 | 00A | Make the existing `portwatch` child folder the independent Git repository root and use `main`. | The parent `dataEngineering` folder is unrelated and has no Git repository; PortWatch is already isolated. |
| D-009 | 00A | Adapt Flux's text normalization and contributor workflow now; defer CI to Step 05A. | Python cleaning and database integration tests are introduced in later stages, so a meaningful Validate workflow belongs with them. |
| D-010 | 01 | Freeze 2024-01-01 UTC as the first one-day NOAA OCM GeoParquet replay. | The exact daily URL returned HTTP 200, supported byte ranges, and exposed a real 16-field timestamped point schema. The old NOAA ZIP URL returned 404. [`configs/demo.yaml`](../configs/demo.yaml) owns dates, URL, source ID, and replay interval. |
| D-011 | 01 | Keep historical replay independent of AISStream credentials; keep present-day GDELT news out of the 2024 replay. | No live key is configured, and recent-news access cannot establish historical article context. Matching-period historical weather can augment replay, but source failures remain explicit. |
| D-012 | 02 | Use immutable SHA-256 raw revisions with recovery sidecars published before payload rename and PostgreSQL registration afterward. | A crash on either side of rename has an explicit discoverable state; no filesystem/database atomic transaction is claimed. See [DATA_CONTRACTS.md](DATA_CONTRACTS.md). |
| D-013 | 02 | Apply numbered SQL once, checking stored checksums under a transaction advisory lock. | Concurrent migration commands cannot apply the same change twice; edited migration history fails instead of silently changing data. |
| D-014 | 02 | Use the already installed PostgreSQL 17 binaries for an isolated localhost cluster at port 55432. | Docker is absent, but existing binaries allow real Step 02 integration verification at $0. Cluster data lives in ignored `pgdata/portwatch`, with local `.env` overrides. Existing PostgreSQL services/databases are untouched. PostGIS remains a later spatial prerequisite. |
| D-015 | 02 | Keep PostgreSQL primary and record Railway as the user's deployment preference. | Deployment is deferred; Step 02 requires local storage and the $0 budget still applies. No cloud service or account was provisioned. |
| D-016 | 03 | Extract the audited NOAA GeoParquet in batches of at most 65,536 rows; limit transfers to 512 MiB/day and backfills to 7 UTC days. | The frozen day yields 62,159 regional observations from 7,293,408 national rows at a measured 222.02 MiB process peak. Preserve all provider fields and unchanged raw bytes; unsupported ranges fail. |
| D-017 | 03 | Default to the verified cached snapshot; use explicit `--refresh` and a separate current-source pointer for remote revisions. | No unnecessary redownload. Changed content or extraction parameters retain distinct immutable identities; a provider rollback can reuse older bytes without altering original receipts. |
| D-018 | 03 | Use `noaa-la-subset-v2` and label times `provider_documented_utc`, preserving actual seconds. | NOAA describes nearest-minute preprocessing, but 61,496 of 62,159 regional timestamps contain nonzero seconds. Do not assert literal minute quantization or a fixed cadence. See [SOURCE_AUDIT.md](SOURCE_AUDIT.md). |
| D-019 | 04 | Use a single compressed server-side AISStream subscription for the configured LA box and six position/static types. | Current provider docs require prompt subscription, document binary JSON and confirmation, and limit concurrent account/IP connections. No dashboard or analytical dependency. See [RUNBOOK.md](RUNBOOK.md). |
| D-020 | 04 | Preserve exact decompressed payload bytes in versioned base64 JSONL envelopes, with a separate durable active spool. | Receipt time, session and sequence provide lineage without rewriting source JSON. Periodic fsync, short rotation and bounded recovery preserve readable records and report incomplete tails; raw publication reuses Step 02. |
| D-021 | 04 | Bound buffering; stop explicitly on queue pressure and drain the held overflow record. | Unbounded memory and silent local drops are unacceptable. Transient failures reconnect with jitter; rejection/policy failures require action. Joined filesystem workers and serialized status writes protect shutdown ownership. |
| D-022 | 04 | Finish offline implementation while marking real live collection unverified until a key exists. | All synthetic/local checks and PostgreSQL integration pass; no external observation or coverage count can be claimed. Historical replay remains usable at $0. |
| D-023 | 05 | Add private native PG17/PostGIS3.6.2 runtime without Docker. | Official Windows bundle is verified by pinned SHA-256, overlaid on copies of installed binaries in ignored `pg-runtime`; only PortWatch's existing cluster was restarted, with data preserved. [Official distribution](https://postgis.net/documentation/getting_started/install_windows/released_versions/). |
| D-024 | 05 | Use NOAA documented UTC observation time; live receipt fallback with separate provider timestamp. | AIS UTC-second is not a datetime and provider metadata time semantics are unverified. Preserve nanosecond text without claiming event-time accuracy. |
| D-025 | 05 | Use separate raw-record and normalized-observation identities with complete outcome lineage. | Stationary observations at distinct times remain; true historical duplicate records retain lineage. Source and dataset prevent accidental NOAA/live merging. |
| D-026 | 05 | Publish batch positions/outcomes/static records/status transactionally using bounded COPY input. | Failed loads cannot expose partial analytical success. Frozen ledger counts and business hashes verify safe replay. Quarantine evidence remains on disk after failures. |
| D-027 | 05 | Flag suspicious motion and preserve optional unknown codes. | AIS sentinels are message-specific; NOAA data is already provider-cleaned. Provisional speed/jump screens do not prove impossible maneuvers or justify throwing away valid positions. |
| D-028 | 05A | Share locked Python quality/package tests and isolated PG17/PostGIS3.6 integration checks between local development and GitHub. | Official actions use verified full-SHA pins; fixtures reject external Python sockets and skipped-only suites cannot pass. Publish previously local Steps01–05 separately with user approval. Account billing lock blocks hosted jobs; keep CI PR unmerged and branch rules unapplied until actual checks pass. |
